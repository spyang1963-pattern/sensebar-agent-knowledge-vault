## 0. 這份文件是什麼

本文件定義一套**通用、可擴充的 AI 影片生成引擎**架構。目的不是「做一支影片」，而是打造一個**平台**：任何人都能「即時、隨興」生出一支有質感的短片。

第一個（也是目前的）應用是**室內設計行銷**（樂之），但它只是**一個領域包（Pack）**，不是引擎的全部。引擎本身不含任何室內設計的專屬邏輯。

---

## 1. 最高原則（不變的道理）

1. **內容為王**：一支片能不能被看，取決於**題材與腳本**，不是特效。工具只是門檻，好腳本無可取代。
2. **產出「有特色、有特點、讓人願意看」的內容**：這是所有 Pack 共同的唯一硬道理。
3. **引擎 ≠ 內容**：引擎提供能力（插槽、渲染、流程），內容（品牌、角色、題材、語氣、資產）全放進可抽換的 Pack。
4. **一切可擴充**：風格、版面、背景、運鏡、配音、字幕、角色、提示詞——每一個維度都要能「丟檔＋登錄一行」就擴充，不改主程式。
5. **零設定可跑，逐層加值**：先有可用的預設，使用者不設定也能出片；想更好再逐項加值。
6. **人在流程中**（可選）：保留審核關卡；但對「即興型」使用者可全自動。

---

## 2. 核心觀念：引擎 vs 內容（Pack）

```
引擎（engine）＝ 通用能力
  插槽（六維度）＋ 風格 renderer ＋ 腳本引擎 ＋ 流程 ＋ 版本管理

領域包（Pack）＝ 一堆設定與資產
  品牌 / 角色 / 題材來源 / 語氣預設 / 資產 / 選配模組
```

同一支引擎，換一個 Pack 就變成另一種用途：

| Pack | 用途 | 是否含行銷模組 |
|---|---|---|
| `interior_lezhi` | 室內設計行銷（樂之） | 是（題材/時間/發布規劃＋稽核回饋） |
| `personal_greeting` | 個人問候（生日、感謝） | 否 |
| `holiday_festival` | 節日祝賀（母親節、開幕） | 否 |
| `product_promo` | 商品/服務介紹 | 可選 |
| …… | 任何領域 | 依需求 |

> 關鍵：**行銷與稽核回饋是「選配模組」，不是引擎的必然**。個人化的節日問候片不需要行銷分析。但「做出讓人想看的內容」是共同底線。

## 4. 六插槽模型（Slot）

**一支片 ＝ 腳本 × 版面 × 背景 × 運鏡 × 配音 × 字幕。**
每個插槽都是一張登錄表；腳本決定「用哪些、怎麼搭配」。

### 4.1 腳本（script）
- **定義**：內容的源頭。旁白句／對話台詞＋每格指示（用照片或文字卡、放哪張、版面、背景、運鏡、情緒）。
- **登錄內容**：無（腳本由 AI 依 Pack 與提示詞產出，非固定清單）。
- **擴充方式**：改 Pack 的 prompt 預設、加風格預設、加自訂提示、加情節規格（§7）。
- **現況**：`script_engine.py`（narr / dialog 兩種）。

### 4.2 版面（layout）
- **定義**：畫面上「元素怎麼擺」的模板。
- **旁白式範例**：照片滿版／照片＋文字卡／上下分割／純文字卡／引言卡／圖表卡。
- **擴充方式**：在 `layout.json` 登錄一個 key＋對應 renderer 函式或模板。

### 4.3 背景（bg）
- **定義**：底圖。可為**程式化產生**（線條風格）或**一張插畫圖**（PNG/JPG）。
- **擴充方式**：`bg.json` 登錄；圖丟進 `assets/bg/`。
- **注意**：通用使用者多無實拍素材 → 背景插畫與 AI 圖是**一級公民**，非選配。

### 4.4 運鏡（motion）
- **定義**：畫面動態。推近／拉遠／平移／肯伯恩斯／微晃／無。
- **擴充方式**：`motion.json` 登錄（名稱＋參數）。

### 4.5 配音（voice）
- **定義**：旁白與角色的聲音。
- **登錄格式**（範例）：
  ```json
  { "provider": "edge-tts",
    "voices": [
      {"key":"narr","name":"旁白","voice":"zh-TW-HsiaoChenNeural","rate":0,"pitch":0},
      {"key":"ren","name":"阿忍","voice":"zh-TW-YunJheNeural","rate":0,"pitch":0},
      {"key":"le","name":"小樂","voice":"zh-TW-HsiaoYuNeural","rate":0,"pitch":0}
    ] }
  ```
- **擴充方式**：新增 voice 條目；未來換供應商（Gemini TTS／ElevenLabs／MiniMax／克隆）＝新增一個 provider 模組，不動主流程。

### 4.6 字幕（caption）
- **定義**：旁白/台詞的文字呈現。
- **樣式範例**：位置（上/中/下）、字級、描邊、色塊、逐字上字、雙語。
- **擴充方式**：`caption.json` 登錄。

## 5. 風格 renderer（styles）

- **定義**：把「腳本＋各插槽選項」實際畫成畫面的程式。**一個風格＝一個 renderer 檔＋登錄一行**。
- **登錄格式**（`styles/registry.json`）：
  ```json
  { "styles": [
      {"key":"narr",  "name":"旁白式",     "renderer":"styles/narr.py",  "format":"narr",
       "supports":["layout","bg","motion","voice","caption"]},
      {"key":"comic", "name":"漫畫對話劇", "renderer":"styles/comic.py", "format":"dialog",
       "supports":["bg","voice","caption","expression"]}
  ] }
  ```
- **窗口的風格下拉由此檔自動生成**；新增風格＝新增 renderer＋登錄，**不改 UI**。
- **現況**：`make_short.py`（narr）、`make_comic.py`（dialog）——尚未登錄化。

## 6. 領域包 Pack 規格

### 6.1 `pack.json`（範例）
```json
{
  "key": "interior_lezhi",
  "name": "樂之室內設計",
  "engine_format_default": "dialog",
  "style_default": "comic",
  "characters": ["ren", "le"],
  "voice_overrides": {"narr": "zh-TW-HsiaoChenNeural"},
  "prompt_presets": ["犀利吐槽", "溫暖專業", "數字權威"],
  "modules": ["topic_planning", "schedule", "distribution", "audit_feedback", "glossary"],
  "brand_file": "brand/profile.json",
  "assets_dir": "assets"
}
```

### 6.2 角色（characters）＝資料，不是程式
每個角色是一份資料：名稱、外觀描述、圖片/線稿資產、聲音、情緒映射。
```json
{ "key":"ren","name":"阿忍","role":"設計師",
  "look":"側分黑髮、圓框眼鏡、鼠尾草綠襯衫",
  "voice":"zh-TW-YunJheNeural",
  "sprite_dir":"characters/ren" }
```
→ **室內設計師只是內建角色之一**；任何人都能加自己的角色。

### 6.3 assets
本包專屬資產：作品照、卡片、背景圖、BGM。

### 6.4 prompt presets
本包的語氣／情節預設（見 §7）。可為每個 Pack 客製。

### 6.5 modules（選配模組）
- **行銷成長模組**（樂之用）：題材規劃、時間規劃、發布規劃、**稽核回饋**（§9）。
- **知識庫/術語校正**（樂之選配）：專業術語校正、作品集對照。
- 個人化 Pack 可全部不掛。

### 6.6 兩種典型 Pack
| | 營運型（樂之） | 即興型（個人節日/問候） |
|---|---|---|
| 目標 | 獲客、行銷 | 表達心意 |
| 題材 | 預先規劃佇列 | 當下臨時 |
| 模組 | 規劃＋發布＋稽核回饋 | 無 |
| 流程 | 三關卡審核 | 一鍵即出 |
| 素材 | 實拍作品（設計師提供） | 多用文字卡/背景 |

## 7. 腳本引擎（prompt 組裝與版本化）

**最終 prompt ＝ 基礎預設 ＋ 風格預設（可選）＋ 情節規格（可選）＋ 自訂提示（可選）**

- **基礎預設**：零設定就能跑（現有 prompt 即此）。
- **風格預設集（preset）**：犀利吐槽／溫暖專業／懸念開場／數字權威／故事化…
- **自訂提示**：使用者自由輸入（例：「務必提到水電追加」「針對透天」「對象是媽媽」）。
- **情節規格**：勾選是否要 案例／數字／反例／轉折／CTA；對話劇可加 **3–5 個情節節拍（起承轉合）**，讓 10 句有起伏。
- **可重現**：以上選擇**存回題目**，同一題可重產、可比較。
- **兩種格式**：`narr`（旁白分鏡）與 `dialog`（二人對話短劇）。

> 「即興型」使用者的 minimal 輸入：對象／主題／想說的話 → 引擎自動補齊語氣與結構。

## 8. 版本化與產出管理

解決現況痛點：**能重產，但同名覆蓋；一題同時只有一支；風格不可選。**

- **命名規則**：`{topic}__{style}`（＋`_v2`、`_v3`…）。
  - 腳本：`scripts/quote_checklist__narr.json`、`scripts/quote_checklist__comic.json`
  - 成品：`output/quote_checklist__comic/`
- **多版本並存**：同一題可同時有旁白版＋漫畫版＋v2…，互不覆蓋。
- **狀態非鎖**：`done` 只代表「已有成品」，可隨時再產新版本。
- **窗口**：列出每題所有版本，各自可再產、可挑一支定稿。
- **風格可選**：產腳本時以窗口選單覆寫該題格式（存回題目）。

## 9. 稽核回饋機制（選配模組，樂之）

**目的**：從「產出」走到「有效」。分析影片的**點閱／互動／諮詢**效度，回頭調整題材與方向。

- **輸入**：平台數據（點閱、按讚、留言、私訊、諮詢數…）。
  - 起步：**手動/CSV 匯入**（各平台自動抓取成本高，先可人工）。
  - 進階：接平台 API（YouTube 可全自動；IG/小紅書/TikTok 多為半自動）。
- **資料存放**：`packs/interior_lezhi/published/{film}.json`（發布時間、平台、數據時序）。
- **分析產出**：
  - 各題材/支柱/風格的**效度排行**（哪類題材帶來最多諮詢）。
  - **建議**：下一輪題材與方向、發布時段、風格調整。
- **回饋迴路**：分析結果 → 寫回 `topics/queue.json`（新增/加權/淘汰題目）。
- **閉環**：
  ```
  題材規劃 → 產腳本 → 審核 → 產片 → 發布 → 收集數據 → 效度分析 → 回饋題材規劃
  ```

## 9A. 工作流介面地圖與模組資料公約（介面預留原則）

**原則：螺旋式發展 ＋ 預留形狀。** 不預建空殼 UI，只預留「**開關 ＋ 資料公約**」；日後加一個模組＝加一個面板，主程式不動。

### 9A.1 總開關：Pack 的 `modules`
`pack.json` 的 `modules` 清單即「這個 Pack 啟用哪些功能」。**UI 依 modules 生成區塊**，未列出的模組不顯示。樂之目前：`topic_planning / schedule / distribution / audit_feedback / glossary`。→ 這份清單**就是介面的預留**：模組在、面板才在。

### 9A.2 脊椎：成品 `metadata.json`
每個成品資料夾的 `metadata.json` 是「產製 → 發布 → 稽核」共同的鍵。欄位公約：
```json
{ "pack": "interior_lezhi", "topic_id": "quote_checklist", "style": "comic",
  "version": 1, "date": "2026-10-18", "title": "…",
  "video": "…mp4", "cover": "封面.png", "subtitle": "subs/…srt",
  "duration_sec": 47.8, "size": "1080x1920" }
```
下游（發布、稽核）之後**往上加** `publish` / `metrics` 等欄位即可，**不必回頭改產線**。

### 9A.3 工作流介面地圖
| 階段 | 介面 | 模組 | 資料公約 | 現況 |
|---|---|---|---|---|
| 題材規劃 | 許願池（佇列） | `topic_planning` | `topics/queue.json` | ✅ |
| 產製 | **產出庫**（瀏覽／播放／標記） | —（核心） | `output\*\metadata.json`＋`封面.png` | 待建 |
| 發布規劃 | 排程＋平台＋狀態 | `schedule` / `distribution` | `schedule.json`、`publish.json` | ✗ |
| 稽核回饋 | 數據匯入＋成效報表 | `audit_feedback` | `audit\metrics.csv`、`audit\report.md` | ✗ |
| 設定 | 狀態列 | —（核心） | `settings.json` | ✅ |

### 9A.4 各模組資料公約（草案）
- **`schedule`（發布排程）**：`schedule.json`＝`{"items":[{"film":"…","planned_date":"2026-10-20","slot":"11:00"}]}`
- **`distribution`（平台發布）**：`publish.json`＝`{"<film>":{"platforms":[{"name":"youtube","url":"…","status":"scheduled|published","at":"…"}]}}`
- **`audit_feedback`（稽核）**：`audit\metrics.csv`（手動／CSV 匯入；欄位：film,date,views,likes,comments,dms,consults）→ `audit\report.md`（依題材／風格彙總，回饋佇列）
- **`glossary`（術語）**：`glossary.json`（術語校正對照）

### 9A.5 落地順序（一石三鳥）
1. 成品 `metadata.json` 補 `pack / topic_id / style / version / date`（兩個 renderer 小改）。
2. **產出庫**（讀 metadata：瀏覽／播放／標記）＝ 同時是**發布與稽核的地基**。
3. 依 `modules` 逐個長出「發布規劃」「稽核回饋」面板。

> 洞見：產出、發布、稽核**都繞著同一份成品 metadata 轉**；先把產出庫與 metadata 做實，後面兩塊自然能隨時掛上。

## 10. 使用流程

### 營運型（樂之）
```
[規劃] 題材佇列 → [關卡1] 審腳本 → [關卡2] 審視覺 → [關卡3] 審成片
   → [發布] 排程/平台 → [稽核] 收數據 → [回饋] 調整題材 → 回到 [規劃]
```

### 即興型（個人/節日）
```
選 Pack → 選情境模板 → 填 1–3 欄（對象/主題/想說的話） → 產腳本 → 一鍵出片
```

## 11. 分階段實作路線

- **P0｜抽出 core（不改變行為）**
  建 `engine/`、六插槽登錄表、風格 registry、prompt 組裝、版本化命名。
  現有 renderer 先「包裝」進 registry，不改其內部。
- **P1｜樂之收成第一個 Pack**
  `packs/interior_lezhi`：品牌、角色、題材、資產、模組移入。**驗證行為不變**。
- **P2｜第二個 Pack 驗證通用性**
  做一支 `personal_greeting` 或 `holiday_festival` 短片（無行銷模組）→ 證明引擎真的通用。
- **P3｜加值**
  背景插畫庫／AI 圖掛上；運鏡/版面變體擴充；voice registry＋供應商；稽核回饋模組。
- **P4｜工作流介面（見 §9A）**
  ①成品 `metadata.json` 補脊椎欄位 → ②**產出庫**（瀏覽/播放/標記，依 `modules` 顯示）→ ③發布規劃（`schedule`/`distribution`）→ ④稽核回饋（`audit_feedback`）。每步皆「加模組＝加面板」，不回頭改產線。
- **橫向（可並行）**：插槽化 `make_short`（讓旁白式的版面/運鏡/背景/字幕可切換）。

## 14. 名詞表

- **引擎（engine）**：通用能力層，不含領域內容。
- **Pack（領域包）**：一組內容設定與資產，決定「這是什麼樣的影片」。
- **Slot（插槽）**：可組合的維度（腳本/版面/背景/運鏡/配音/字幕）。
- **Style（風格）**：一個 renderer，負責把插槽選項畫成畫面。
- **Preset（預設）**：可選的 prompt 片段（語氣/結構）。
- **Module（模組）**：Pack 的選配功能（行銷、稽核回饋、術語…）。
- **營運型/即興型**：兩種 Pack 典型（長期行銷 vs 臨時個人）。

## 16. P5 視覺多樣性：slot 接線

### 16.1 問題

背景與運鏡原本是**機械輪替**：`make_comic.py` 依序號取 `BG_KINDS[i % 5]`、`script_engine.py` 依 `k % 2` 交替 in/out、`make_short.py` 只認 `zoom` 欄位。插槽登錄表（`engine/slots/*.json`）當時只是文件，沒有任何程式讀它 → 十幾支片看起來都一樣。

### 16.2 原則

**插槽的值由內容決定，順序只是 fallback。** LLM 在編劇階段依每句語意選插槽值；renderer 只負責畫；登錄表是唯一真相——改 JSON 就能增選項，prompt 與驗證自動跟著變（`registry.slot_keys()`）。

### 16.3 已實作（2026-10-19，commit 待定）

- **registry**（`engine/core/registry.py`）：新增 `slot_keys()`／`slot_entries()`／`slot_entry()`；新增插槽檔 `look.json`。
- **腳本端**（`lezhi/tools/script_engine.py`）：dialog prompt 要求每句填 `bg`（含語意規則）＋整支填 `look`；narr prompt 要求每句填 `motion`；`assemble*()` 做值域驗證、別名轉換（`in`→`kenburns_in`）、相鄰去重；無效值退回依序 cycle＝舊行為。
- **narr renderer**（`make_short.py`）：`build_clip` 支援 `kenburns_in/out、pan_left/right/up、shake_soft、none`（ffmpeg zoompan ＋ clamp 表達式）；腳本欄位改名 `motion`，`zoom` 仍相容。
- **dialog renderer**（`lezhi/tools/make_comic.py`）：讀 `script["look"]`（`--look` 可覆寫）→ `apply_look()` 重綁墨／紙／品牌色＋背景分級（`warm/night/sage/ink`，`ink` 連角色一起灰階）；`bg` 值域檢查，未實作 key 退回 cycle。

### 16.4 驗證

35 項單元檢查全通過（值域／別名／相鄰去重／7 種運鏡 ffmpeg 實跑／分級像素比對）。真實生成結果：narr 的 motion 依內容（驚嚇句→`shake_soft`、列舉句→`pan_right`）；dialog 的 bg 依內容（報價→`plain`、施工→`site`、吐槽→`cafe`），避坑類自動選 `ink`。視覺差異可量化：`working/p51/comic_ink` 與 `comic_warm` 同一腳本，色度 0.56 vs 28.81。舊腳本（只有 `zoom`／沒有 `bg`）照常渲染。
