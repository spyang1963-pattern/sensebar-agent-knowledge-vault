# XQ-AI神隊友 — 給 Claude Code 的工作說明

這個資料夾是一套「盤中看盤」的固定作法（SOP）。使用者開口說要跑哪一個，你就照下面的流程做：
**抓快照 → 跑分析腳本 → 依規格寫報告存檔**。不要自己發明新步驟、不要跳過旗標檢查、不要改腳本（除非使用者要求）。全程繁體中文。

## 這裡有什麼

| 路徑 | 用途 |
|---|---|
| `routines/snapshot.ps1` | 從正在執行的 Excel（XQ 用 DDE 貼過來的報價表，通常沒存檔）抓即時快照 → `routines/snapshots/{kind}_yyyyMMdd_HHmmss.csv` |
| `routines/analyze_rank.ps1` | 作法一 族群資金排行 的計算（成交值前 50 名） |
| `routines/analyze_breadth.ps1` | 作法二 齊漲分歧診斷 的計算（成交值前 200 名） |
| `routines/analyze_notes.ps1` | 作法三 盤中觀察三段 的事實清單（全樣本，並與上一份快照比較） |
| `routines/groups.ps1`（＋選用 `groups_extra.ps1`） | 代碼 → 族群 對照表。**使用者長期維護的唯一檔案** |
| `routines/check_env.ps1` | 安裝檢查 |
| `routines/outputs/` | 你寫的報告存這裡 |
| `範例報告/` | 三種報告各一份完整範例 ＋ `範例快照/`（可拿來測試分析腳本）。**報告格式以範例為準** |
| `排程範本.md` | 使用者要建排程（Routines）時照抄的提示詞與 cron |
| `圖解教學.html`、`開始使用.md` | 給人看的教學；使用者問「怎麼用」先請他看這兩個 |

三支分析腳本的輸出是給你讀的純文字資料（`|` 分隔），不是報告。報告是你寫的。

## 使用者會這樣說 → 你要做什麼

| 使用者說的話（大意即可） | 做法 |
|---|---|
| 跑族群資金排行／作法一／錢流到哪／跑排行 | 共同流程，Kind = `rank`，寫「族群資金排行」報告 |
| 跑齊漲分歧／作法二／整組還是一檔／診斷 | 共同流程，Kind = `breadth`，寫「齊漲分歧診斷」報告 |
| 跑盤中觀察／三段／作法三／寫三段 | 共同流程，Kind = `notes`，寫「盤中觀察三段」報告 |
| 三個都跑／跑一輪／全部跑 | 依序做三次（rank → breadth → notes），每一個都要自己抓快照，不要共用 |
| 檢查環境／安裝檢查／能不能跑 | 跑 `check_env.ps1`（要 -STA），把結果用白話回報 |
| 補分類／這幾檔歸到某族群／未分類怎麼辦 | 改 `routines/groups.ps1`（或 `groups_extra.ps1`），重跑對應分析確認判定有沒有變，回報差異 |
| 分析這份快照 xxx.csv／用範例跑看看 | `analyze_*.ps1 -File <路徑>`（範例在 `範例報告/範例快照/`） |
| 強制跑／現在不是盤中也要跑／測試 | `snapshot.ps1` 加 `-Force`；報告要標明「非盤中測試」 |
| 建排程／設 routine／每半小時自動跑 | 依 `排程範本.md` 用排程工具建立：cron `0,30 9-13 * * 1-5`（週一到五 09:00–13:30 每 30 分），排程提示詞要寫完整並以「先讀取 <本資料夾>\CLAUDE.md」開頭；建好後告訴使用者三樣東西要開著（電腦、Claude Code、Excel 報價表），09:00 那次會被 SKIP 擋掉 |
| 停用排程／改排程時間 | 用排程工具停用或更新 cron，回報新的執行時間 |

> **排程執行時**（每次都是全新的對話）：照一樣的共同流程跑；`SKIP=1`／`stale=1` 就安靜結束，不寫報告；抓不到 Excel 就在對話裡說明原因，不要用舊快照頂替。

## 共同流程（三個作法都一樣）

### 步驟 0：先確認 Excel 報價表開著

```powershell
Get-Process EXCEL -ErrorAction SilentlyContinue | Select-Object Id, StartTime, MainWindowTitle
```

- `MainWindowTitle` 有活頁簿名稱（例如「活頁簿1 - Excel」）→ 可以跑。
- 沒有 EXCEL 行程，或 `MainWindowTitle` 是空的（常見：前一天殘留的 Excel）→ **停下來**，請使用者在 XQ 做「輸出欄位 → 選 DDE 伺服器 → 確定」把報價表貼到 Excel（不用存檔），做好再說一聲。**不要拿舊快照頂替、不要編造數字。**

### 步驟 1：抓快照（一定用 -STA 開新的 powershell.exe）

```
powershell.exe -STA -NoProfile -ExecutionPolicy Bypass -File "<本資料夾絕對路徑>\routines\snapshot.ps1" -Kind rank
```

`<本資料夾絕對路徑>` 就是你目前的工作目錄（含 CLAUDE.md 的那層）。路徑有空格或中文都要加引號；從 Bash 工具呼叫時反斜線要寫成 `\\` 或改用 `/`。優先用 PowerShell 工具執行。

看輸出**第一行**的旗標再決定要不要繼續：

| 旗標／訊息 | 意思 | 你要做的事 |
|---|---|---|
| `SKIP=1` | 非盤中時段（09:25–13:55 以外） | 停止，告訴使用者非盤中；使用者明確要測試才加 `-Force` |
| `stale=1` | 和上一份同類快照完全相同（休市／報價中斷／Excel 停住） | 停止，不寫報告，說明比對到哪一份 |
| `stale=0` | 新資料，已存檔 | 繼續 |
| 錯誤含 `0x8001010A`／`RPC_E_SERVERCALL`／`80010001` | Excel 有儲存格在編輯狀態 | 請使用者切到 Excel 按 Esc，再重跑一次 |
| 「找不到含『代碼/成交/漲幅%』標題列的報價工作表」且沒有錯誤碼 | 活頁簿被關了 | 回步驟 0 |
| 回傳非零 exit code，但 `snapshots/` 裡已經有這次的新檔 | 假警報 | 直接往下 |

### 步驟 2：跑分析腳本

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<本資料夾絕對路徑>\routines\analyze_rank.ps1"
```

`analyze_breadth.ps1`／`analyze_notes.ps1` 同理。腳本會自動抓最新的對應快照，不必傳參數。**輸出全部讀完再寫報告**，每個數字都從輸出裡拿。

各腳本的口徑（報告表頭要寫清楚，整份報告只用一種口徑，不要混）：

| 腳本 | 口徑 |
|---|---|
| `analyze_rank.ps1` | 剔除 TSE／OTC 指數列後，成交值前 50 名；族群佔比 ＝ 族群合計 ÷ 前 50 合計 |
| `analyze_breadth.ps1` | 成交值前 200 名（表頭要註明第 200 名的成交值是多少） |
| `analyze_notes.ps1` | 全樣本（快照裡所有個股），並與上一份 notes 快照比較 |

若你另外用 Python 讀 CSV 做全樣本計算（CSV 有 BOM，請用 `encoding='utf-8-sig'`），要在報告裡註明是全樣本，不要和腳本的前 N 名數字混在同一段。

輸出末尾的「未分類」清單，要原樣列進報告最後一節，請使用者補進 `groups.ps1`。**不要自己硬塞進相近族群。**

### 步驟 3：寫報告存檔

- 檔名：`routines/outputs/{yyyyMMdd_HHmm}_{報告名}.md`，時間用**快照擷取時間**（snapshot 輸出第一行的時戳），報告名就是「族群資金排行」「齊漲分歧診斷」「盤中觀察三段」其中之一。
- 格式嚴格依照 `範例報告/` 裡的同名檔案（段落、表格欄位、結尾免責都照抄結構）。
- 寫完在對話裡貼出重點（結論段／三段文字），並告訴使用者檔案路徑。

### 步驟 4：推播（選用）

只有最下方「推播設定」有填 chat_id 才做；沒填就**直接跳過，不要報錯、不要追問**。

## 文體通用規則（三份報告都適用）

借用了知識庫「每日／深度報告」的易讀寫法，三份報告共用以下四點骨架，讓掃讀更快、意思更清楚：

1. **一句話結論**：標題後第一行，用一行講出這份快照最重要的一件事（大到「錢在哪、是齊漲還是退潮」，不留到最後）。讀者看到這裡──要有「啊，今天就是這樣」的感覺。
2. **欄位口語翻譯**：技術字段（內外盤比、乖離 dev%、換手率、均價）在**首次出現**時，加一句括號或小字口語說明，例如「內外盤比 36.96（外盤只佔不到四成，賣方主導）」「乖離 -1.85（成交價低於均價，收在均價下方）」。同一欄位之後再出現就不必重複。
3. **「這代表什麼」**：凡是矛盾、反差、分歧，不只列「誰漲誰跌、多少錢」，結尾必定補一句把數據合起來的含義（例如「量最大卻收黑＝資金留在舊主軸但股價不認帳」「上中下游同紅＝題材而非個股消息」）。這正是知識庫深度報告「事件→影響」那套的縮小版，但**只詮釋已發生的事實，不預測**。
4. **該盯的變數**：結尾免責前，列出這份快照裡接下來 2-3 個值得追蹤的客觀訊號（例如「載板龍頭能否止跌翻紅」「爆量個股的高換手是否擴散」）。**只描述訊號，不帶看多看空方向、不給操作建議**。

鐵則不變：不預測、不給買賣建議、不引用外部資料、數字全從快照與腳本輸出。

## 作法一：族群資金排行 — 報告規格

> 文體通用規則（三份報告都適用，詳見上方「文體通用規則」）：
> ① 標題下第一行＝「一句話結論」；② 首次出現的技術欄位要加一句口語翻譯；③ 每個矛盾／反差結尾要總結「這些數據合起來說明什麼」；④ 結尾免責前加「該盯的變數」。

1. **表頭資訊**：擷取時間、快照檔名、工作簿名稱、全表檔數、前 50 名成交值合計、大盤對照（加權／櫃買指數與漲跌幅）。
2. **一句話結論**（標題下第一行，用小標）：一句話講出「今天錢最集中在哪、是齊漲還是退潮」，像「大資金停在載板卻在退潮、小股數的組裝端才在往前走」。
3. **族群資金表**，依成交值合計由大到小：`族群｜檔數｜成交值(億)｜佔前50比重%｜平均漲幅%｜漲跌家數｜代表股(成交值／漲幅)`。
4. **結論**：明確講出資金流入最多的族群、金額、佔比，以及它是否為「上中下游同時進榜」的結構（材料、基板、板廠等多層都有錢通常代表題材；只有單層代表個股消息）。若成交值最大的族群其實方向偏弱，要直說「量大卻退潮」，別只報金額。
5. **反差提醒**（最有價值的一段，不要省略）：
   - A. 成交值排名很前面、但股價收黑的個股（各列一到三檔，說明矛盾在哪：內外盤比、乖離、委買委賣厚度）
   - B. 族群整體強勢、但集團關聯股或同業走弱（例如南亞科漲、南亞跌）
   - 每一檔或每一組反差，結尾補一句「這代表什麼」——把數據合起來的含義講明（例如「量最大卻收黑＝資金留在舊主軸但股價不認帳」），不要只堆數字。
6. **該盯的變數**（免責前）：列出這份快照裡接下來最值得追蹤的 2-3 個客觀盤面訊號（例如「載板龍頭欣興能否止跌翻紅」「聯傑的高換手是否擴散」），**只描述訊號，不帶看多看空方向**。
7. **待補族群對照**：未分類清單；若沒有就寫「無」。
8. 結尾一行免責：盤中快照、只描述資金結構、不含買賣建議。

歸類原則：用產業／供應鏈位置分群，上中下游分開（ABF載板 ≠ 銅箔基板CCL ≠ PCB）；名字相近但產業不同要分清楚（南亞科＝記憶體、南亞＝塑化）。

## 作法二：齊漲分歧診斷 — 報告規格

判定門檻（腳本已內建，報告文字要和腳本一致；使用者改了腳本門檻就照新的寫，並在表頭註明）：

| 層級 | 規則 |
|---|---|
| 齊漲 | 上漲檔數 ÷ 樣本數 ≥ 0.75，且上漲至少 3 檔 |
| 齊跌 | 下跌檔數 ÷ 樣本數 ≥ 0.75，且下跌至少 3 檔 |
| 內部分歧 | 同時存在漲幅 ≥ +3% 與 ≤ −3% 的成員 |
| 個別表現 | 族群內僅 1 檔漲幅 ≥ +5%，其餘全部落在 ±2% 以內 |
| 樣本不足 | 族群有效樣本 < 3 檔，不判定整齊度，列入附註 |
| 漲停鎖死 | 漲幅 ≥ +9.5% 且委賣 = 0 ｜ 跌停鎖死：漲幅 ≤ −9.5% 且委買 = 0 |
| 換手異常 | 換手率 ≥ 10% |
| 假強勢 | 漲幅 > 0 但 dev% ≤ −1.5（收在均價下方） ｜ 隱藏買盤：漲幅 < 0 但 dev% ≥ +1.5 |
| 量大走弱 | 成交值前 30 名且漲幅 ≤ −2% |

報告結構（套用文體通用規則：一句話結論＋欄位翻譯＋這代表什麼＋該盯的變數）：
1. **一句話結論**（標題下第一行）：用一行點出這張盤面最大的一件事（例如「最大資金族群在退潮、小盤組裝端才在走」）。
2. **表頭**：擷取時間、快照檔、分析範圍（成交值前 200 名＋第 200 名成交值）、大盤、前 200 名與全表漲跌家數、未分類檔數與分類涵蓋率。
3. **齊漲族群表**：族群、整齊度（如 7/7 全漲）、成交值合計、漲停鎖死檔數、成員與各自漲幅。依整齊度排序。
4. **齊跌族群表**：同格式。
5. **內部分歧族群**：表列後，一定回答「成交值最大的族群是否其實在分歧」——若最大資金族群同時有大漲與大跌成員，要明講這不是族群行情、是資金在族群內挑選，並補「這代表什麼」。
6. **個別表現**：逐檔說明為什麼算獨走（同族群其他成員在幹嘛），附換手率——低換手就鎖漲停跟高換手才漲停，意義完全不同。沒有就說明最接近的幾檔為何不算。
7. **個股訊號清單**：漲停鎖死、跌停鎖死、換手異常、假強勢、隱藏買盤、量大走弱，各自表列附數據，每節一兩句點評，並把同類訊號合起來說一句含義。
8. **樣本不足**清單。
9. **最反直覺的一件事**：3 到 5 句，指出這份快照裡最違反直覺的發現（例如成交值最大的族群其實在退潮、上游紅下游黑）。這段是重點，一定要寫。
10. **該盯的變數**：免責前列出 2-3 個客觀追蹤訊號，不帶方向。
11. 結尾免責。

## 作法三：盤中觀察三段 — 寫作規格

先從 `analyze_notes.ps1` 的輸出把事實算清楚（族群成交值與佔比、漲跌家數、漲停鎖死、換手 ≥ 10%、假強勢、台積電與指數是否脫節、與上一份的差異），再動筆。

三段各一個重點、彼此不重複。可用的角度（挑最有訊息量的三個，不要硬湊）：
- 資金主軸落在哪個族群，族群內部是同調還是分歧
- 哪些族群整齊度最高（尤其成交值不大但多檔漲停鎖死的，代表籌碼還輕）
- 哪個族群「量還在但人已經在走」（成交值大卻多數成員走弱）
- 權值股與二線股是否脫節（台積電幾乎不動、中小型激烈）
- 齊跌族群或跌停群聚
- 低換手就鎖漲停的個股（籌碼極輕）
- **這個時段才出現的變化**（新增鎖死、剛翻黑的族群、換手突然衝高）——一天會跑很多輪，這一輪要盡量跟前面不同，優先寫變化
- **最後一輪（13:30 收盤後）**：把本次與前一份快照相減就是尾盤集合競價的成交分布，優先用這個角度

寫作要求：
- 每段 4 到 6 句，開頭一句小標點出重點。
- **每個判斷都要帶具體數字**（成交值幾億、漲幅幾%、換手率幾%、委買委賣張數），不要出現「表現強勁」「量能充沛」這類沒有數字的空話。
- 語氣像交易員寫給自己的盤中筆記，不是新聞稿，不要用「值得投資人留意」這類套話。
- 三段之間要有邏輯落差，最好其中一段推翻另一段的直覺。
- **報告標題下第一行＝「一句話結論」**：一句話點出這一輪盤面的主軸（例如「最大資金在退潮、小盤組裝端才在走」），讓掃讀先抓到重點。
- **結尾免責前加「該盯的變數」**：列 2-3 個接下來值得追蹤的客觀訊號，不帶方向。
- 所有數字以本次快照為準；上一份只用來描述變化。

報告結構：表頭（擷取時間、快照檔、比較基準、資料範圍、口徑說明）→ ①②③ 三段 → 「本次引用的關鍵數據」（指數與廣度、族群成交值前 8 名含增量、三段各自引用的清單、換手 ≥ 10%、假強勢、量大走弱、其他大幅位移、未分類）。

## 鐵則（每一份報告都適用）

- 只描述已經發生的盤面事實與資金結構。**不做買賣建議、不推測目標價、不預測明日走勢、不用「可以買」「留意進場」這類措辭。**
- 所有數字必須來自本次快照與腳本輸出，不得引用記憶或外部資料。
- 報告標明擷取時間；盤中快照之後還會變。
- 未分類不要硬塞，列清單請使用者補 `groups.ps1`。
- 樣本不足 3 檔的族群不判定整齊度。
- 腳本回傳的數字不要自己四捨五入改精度，照抄。

## 推播設定（選用）

```
TELEGRAM_CHAT_ID = （未設定）
```

有裝 Telegram 外掛（工具名通常是 `mcp__plugin_telegram_telegram__reply`）且上面填了 chat_id 才推播，規則：
- `format` 用 `text`，**不要用 markdownv2**（報價數據充滿 `.` `-` `+` `%` `(` `)`，漏轉義一個整則失敗）；文字裡也不要用 `**粗體**`。

- 作法一、二發摘要；作法三直接發完整三段。
