### 事件 C 的實作（notebook 版，2026-11-20）

SDK `google-genai 2.16.0` 的 `HttpOptions.timeout` 單位是**毫秒**，`Client(http_options={...})` 支援。

1. `GEMINI_TIMEOUT_MS = 180000`（180 秒）。
2. 新增 `_new_gemini_client(api_key)`：**唯一**建立 Gemini client 的出口，帶
   `http_options={"timeout": GEMINI_TIMEOUT_MS}`；原本三處直接 `genai.Client(api_key=...)`
   （`gemini_note`／`gemini_summary`／`gemini_summary_merge`）全部改走它。
3. 新增 `_is_retryable(exc)`，把 `timed out`／`timeout`／`deadline exceeded`／`disconnected`／
   `connection reset`／`connection aborted`／`remote end closed` 納入暫時性錯誤
   （同時比 exception 訊息與 class 名稱，例如 `httpx.ReadTimeout`）。
   `_gemini_call`（內層 6 輪）與 `_retry_llm`（外層 3 輪）共用。
   **這一步很關鍵**：只有加 timeout 而沒把 timeout 列入重試，會從「無限卡」變成「直接 failed」。
4. 效果：stalled request 最多 180 秒拋錯 → 內層重試 → 外層重試 → 持續失敗才 failed。

驗證（`working/_test_gemini_timeout.py`，不進 git）：

```text
client http_options.timeout=180000

```

## 2. 通用 SOP：任一機踩雷怎麼辦

### 步驟 1：先自救，保留證據（踩雷機）

- 卡住的進程：記下 PID、開始時間、CPU 時間、TCP 連線對象（这次是 `172.217.114.4:443`），再砍。
- 任務狀態：`shared/tasks/task_<id>.json` **和** mirror `task_status.json` 兩邊都要改
  （`shared` 才是 worker 唯一來源；只改 mirror 會被 `sync_shared_to_local()` 蓋回去）。
- 清過期 lock／進度檔；**讓 GUI 自己重生 worker**，不要手動另開（會雙 worker）。
- 證據與本機報告放 `working/`（已 gitignored），例如 `working\_rename_..._manifest.json`。

### 步驟 2：定性——是「本機資料」還是「程式碼」

| 類型 | 例子 | 處理 |
|---|---|---|
| 本機資料 | 檔名日期誤植、單一任務卡死、KB 本機副本錯 | 各機自己修，**不進 git**；通知其他機「檢查自己有沒有相同副本」即可 |
| 程式碼 | timeout 缺失、解析 bug、去重規則錯、`.bat` 換行 | **只改一份**，由 notebook 統一 commit/push；其他機不要各改各的 |

判不準時，先當程式碼問題回報，讓 notebook 判斷。

### 步驟 3：回報格式（照这次 PC2 的格式，很好用）

```markdown
事件 X：一句话症狀
- 症狀：具體數字（PID／CPU／時間／TCP／錯誤訊息）
- 根因：查到哪一行、為什麼
- 處理：本機做了什麼（含指令）
- 驗證：驗證指令 + 結果（rc／比對數）
- 需不需要同步：需要同步的「檔案清單」+ 改動摘要；不需要就明說「僅本機」
- 風險提醒：哪些不能全域改、哪些 archive 不能動
```

回報**貼給 notebook**，不要先 commit（避免兩邊同時改 master 造成分叉）。

### 步驟 4：notebook 查證 → commit → push

- 能讀到該機分享就讀實際檔案；讀不到就像这次照規格在 notebook 重現實作 + 寫測試，**不要凭轉貼照抄**。
- 只 `git add` 認可的程式／文件檔，**不要** `git add task_status.json task_tracker.json`
  （GUI 本機狀態檔，untracked）、`shared/tasks/*.json`、`knowledge-base/*`、`cookies.txt`、本機 log。
- commit 訊息寫「事件代號 + 改了什麼 + 驗證結果」，push 後把 **commit SHA + 檔案清單 + 各機要做的動作**
  貼回各機。

### 步驟 5：各機 pull（**本機有未提交修改時會被擋**）

```powershell
cd D:\AI-Agent-Workspace
git fetch origin
git status -sb                       # 確認有哪些本機修改

# 若本機也改過同一支程式（像 PC2 的 make_course_note.py）：
git diff -- make_course_note.py | Set-Content -Encoding UTF8 working\_my_local.diff
git checkout -- make_course_note.py  # 先還原，pull 才不會被擋

git pull origin master
git log -1 --oneline                 # 應等於 notebook 公告的 SHA
python -X utf8 -m py_compile make_course_note.py
```

- **GUI 是長駐程序**：pull 後要關閉重開才會載入新碼。
- worker 若在跑，等它空閒或先停，避免舊碼继续执行。
- 本地 diff 留著比對：pull 後確認 notebook 版是否含自己的修護；
  **若沒有，立刻回報，不要自行再改一份**（那就是分歧的開始）。

#### ⚠ 陷阱：GUI 重開了，但 worker 還在跑舊碼（2026-11-20 PC1 實踩）

**`git pull` 只更新磁碟上的檔，不會更新已經在記憶體裡執行的程序。** 有兩個獨立的長駐程序要處理：

| 程序 | 載入新碼的方式 | 判斷依據 |
|---|---|---|
| GUI（`task_manager_gui.py`） | 關閉重開 | 使用者操作介面 |
| worker（`worker.py`） | **砍掉重啟** | 真正執行 note／summary／youtube 任務 |

關鍵在 `worker.py` 用 `from make_course_note import generate_note` / `generate_summary`
（第 504、575 行）—— 是 **import、不是 subprocess**。Python 一旦 import 就快取在
`sys.modules`，即使 pull 了新版 `make_course_note.py`，舊 worker 記憶體裡仍是舊碼。
**後續 note／summary 任務會繼續用舊版（例如沒有 180s timeout），可能重演事件 B 的無限卡。**

- 判斷要不要重啟：worker 記憶體裡的模組何時載入的？若 worker 是事件 C 修護前就啟動的常駐程序
  （PC1 那顆是 11-07 啟動、PID 19020），一定要重啟。
- 重啟方式（GUI 沒開時不會自動重生 worker，要手動）：
  ```powershell
  Stop-Process -Id <舊PID> -Force
  type working\_worker_<machine>.lock   # PID 已死 → 新 worker 會自動接手，不用手動刪
  start /b pythonw -X utf8 worker.py > logs\worker_<machine>.log 2>&1
  ```
  若想看他主控台，把 `pythonw` 換成 `python`；常駐程序**不要加 `--once`**。
- 同機只能一個 worker（PID lock 擋著，見 `worker.py::acquire_worker_lock`），砍掉舊的再開新的，
  不要兩個並存（會互搶任務，見 #210 事故）。
- 若近期沒有 note／summary 任務，可延後到下次產筆記前再重啟；但只要要讓新任務吃到修護，就必須重啟。

### 步驟 6：收尾

- 各機回報「已 pull 到 SHA、驗證結果」。
- notebook 把事件結論寫進 `docs/incidents/YYYY-MM-DD_<事件>_處理記錄.md`（本檔），
  並視情況補 `AGENTS.md` 的規則，讓下一台不用再踩。

## 3. 紅線（違反過所以寫下來）

1. ❌ 每台各修各的程式 → 版本分歧，之後誰也不知道哪台是對的。
2. ❌ `git add task_status.json` / `task_tracker.json` / `shared/tasks/*.json` / `knowledge-base/*`。
3. ❌ 從 notebook 遠端改 PC1／PC2 的程式：notebook 對它們的分享是唯讀（RX），做不到。
4. ❌ 全域字串替換檔名日期：同一天有多個不同任務（`-0815`／`-1405`／不同講師），會改壞別的影片。
5. ❌ `.bat` 存成 LF-only：`cmd.exe` 解析失敗 → 排程 rc=255、日誌不成長（2026-11-13 事故）。
6. ❌ 加 timeout 卻不把 timeout 列入重試：從無限卡變成直接 failed。
7. ❌ 以為「GUI 重開了＝新碼生效」就放著常駐 worker 不管：`worker.py` 用 import 載入
   `make_course_note`（非 subprocess），pull 後舊 worker 記憶體裡仍是舊碼 → 要砍掉重啟（見步驟 5）。
