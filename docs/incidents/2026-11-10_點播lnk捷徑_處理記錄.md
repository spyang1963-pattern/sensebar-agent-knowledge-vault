## 3. 根因：兩個 Windows／Markdown 限制互撞（2026-11-10 實測矩陣，勿再重試）

| 開法 | 結果 | 原因 |
|---|---|---|
| 純 UNC 路徑 `os.startfile(r'\\ip\YouTube_Videos\中文 檔名.mp4')` | ✅ 可開 | — |
| 純本機路徑 `os.startfile` | ✅ 可開 | — |
| **ASCII 檔名** `file:///D:/.../abc.mp4` | ✅ 可開 | 無編碼問題 |
| raw unicode URI（中文不編碼直接進 URI 字串） | ✅ 可開 | 但 Markdown／部分渲染器不可靠，不採用 |
| percent-encoded 中文 URI `file:///Z:/中文%20檔名.mp4` | ❌ WinError 2 | **ShellExecute／Obsidian 都不會解碼 `%XX`** |
| `file:////ip/…`、`file://ip/…`（遠端＋中文＋編碼） | ❌ WinError 2 | 同上 |
| Z: 槽掛 UNC 後 `file:///Z:/…` | ❌ WinError 2 | 同上（換盤符沒用，問題在編碼） |

**為什麼只能 percent-encode**：Markdown 連結目的地 `[](...)` 不能含空白，
而影片檔名一律是「中文＋空白」（`2026-11-09_【廖崧沂.點靈的飆股思維】….mp4`）。
所以「能寫進 Markdown 的（編碼過）」與「Windows 開得了的（不編碼）」**沒有交集**——
除非把連結指向一個**全 ASCII 檔名的東西**。

**為什麼是 .lnk**：純路徑雖可開但含空白（Markdown 切斷）；
`.lnk` 檔名可全 ASCII（`Vc13tv1jing_burned.lnk`）→ Markdown 安全，
點開時 Windows 解析捷徑內部 TargetPath（可含中文／空白／UNC）→ 播放器開原片。
**兩層都通，2026-11-10 實測點開會播。**

## 4. 解法實作：`fix_video_links.py`（notebook 端）

### 4.1 輸入行格式（兩種都處理）

| 來源 | 行長相 | 寫入者 |
|---|---|---|
| PC 收割 | `- 燒字幕影片（在 PC2）：[▶ 點播](file://<ip>/…)｜\\<ip>\…` | `publish_outbox.rewrite_producer_paths` |
| notebook 本機 | `- 本機影片：[▶ 點播](file:///D:/…)｜D:\…` | `backfill_video_links` |

兩者的 URI 都點不開；行尾「｜原路徑」是 raw 未編碼的，是**解析目標的首選來源**。

### 4.2 輸出行格式（改寫後）

```markdown
- 燒字幕影片（在 PC2）：[▶ 點播](file:///D:/AI-Agent-Workspace/knowledge-base/_video_links/Vc13tv1jing_burned.lnk)｜\\100.113.234.81\YouTube_Videos\2026-11-09_….mp4
```

- 連結 → `knowledge-base\_video_links\<video_id>_video|burned.lnk`（**video_id 優先**，
  沒有才用路徑 sha1 前 12 碼；同 id 兩個存放位置再加雜湊消歧）。
- 行尾原路徑**保留**（可複製貼到檔案總管當後備；也是自動對時的依據）。
- `.lnk` 目錄隨 `nas_backup` 備份；遺失重跑即重建（不驗證目標存在——遠端離線也能先建好）。

### 4.3 自動對時（每晚排程自動做，不必 --force）

- `_targets.json` 記「上次各 .lnk 指去哪」→ 掃描出的目標**變了才重建**該捷徑。
- `sync_machine_ip()`：行尾 UNC 的 host 對照「（在 PCX）」→ `config.TAILSCALE_IPS` 現值；
  **IP 漂移**時行尾 UNC 與 .lnk 目標一起換新（條目行跟著重寫）。
  防誤動護欄：host 若是**別台機器的現值 IP**（label 過時、影片真的在別台）→ 不猜不動；
  本機路徑 → 不動。三情境實測通過。
- `--force` 只供無條件重建（一般不必）。

### 4.4 建捷徑的方式（PowerShell 批次，單次 subprocess）

- `WScript.Shell COM` → `CreateShortcut(...).TargetPath = 目標；Save()`。
- 100 個一批跑一次 PowerShell（不是一支一支 spawn），正常約 3~5 秒。
- 暫存檔（`batch.json`／`mk.ps1`）寫在**系統暫存目錄**（`tempfile.TemporaryDirectory`），
  不落在 KB 裡（早期版本寫在 `_video_links\` 內，會被掃到／污染）。
- **逾時 120 秒＋重試一次**：本日實測過一次 PowerShell 無輸出卡死（建 2 個捷徑花 110 秒、
  探測總計 230 秒，伴隨 opencode 伺服器重啟；機器重啟後恢復 0.7 秒）。
  防護勿移除——排程跑掛比慢更糟。
- `.lnk` 建成判準：檔案存在且 size>0；**有任一沒建成 → 不改寫任何條目**（避免 md 指到
  不存在的捷徑），下次重跑再試。

### 4.5 冪等與順序

1. 先建齊 .lnk → 才寫 md（md 永遠不會指到不存在的捷徑）。
2. 已指捷徑且 URI／行尾路徑都沒變的行 → 完全不動（重跑零動作）。
3. 換 IP／搬 links_dir → 只重寫漂移的行（`對時重寫` 計數）。
4. 排除目錄：`_harvest_conflicts`、`_harvest_overwritten`、`_archive_no_transcript`、`_video_links`。

3. notebook `config.py` 的 `TAILSCALE_IPS` 加／改該機現值 IP。
4. 驗證：`Test-Path \\<tailnet-ip>\YouTube_Videos` → True。
5. 收割一輪後 `fix_video_links.py` 自動把新條目換成捷徑（**不用手動做任何事**）。

### 7.2 產出機換 tailnet IP

- **什麼都不用做**：當晚 `fix_video_links.py` 自動對時（行尾 UNC＋.lnk 目標一起換新）。
- 前提：`config.py` 的 `TAILSCALE_IPS` 已更新現值；cmdkey 也要重存新 IP。
- 疑難時手動：`python -X utf8 fix_video_links.py`（看 log「對時重寫」數）；
  再不行 `--force` 無條件重建。

### 7.3 捷徑點不開時（排錯順序）

1. `.lnk` 在嗎：`ls knowledge-base\_video_links\<video_id>_<video|burned>.lnk`
   → 沒有：跑 `python -X utf8 fix_video_links.py` 重建。
2. 目標在嗎：條目行尾的 UNC／路徑貼到檔案總管
   → 連不上：產出機開分享了嗎、cmdkey 還在嗎（`cmdkey /list`）、tailnet IP 對嗎。
3. 換 IP 了：改 `config.py` → 跑 `fix_video_links.py`（自動換行尾 UNC）。
4. PowerShell 疑似卡死：等 120 秒它會自己逾時重試；連續兩晚失敗看
   `logs\harvest_pc.log` 的 `vidlinks rc=`。

## 8. 切記（踩過的雷，勿重蹈）

1. **不要再把 file:// URI 直接寫成可點連結**——percent-encoded 中文必點不開（第 3 節矩陣）。
   打包時寫的 URI 是「位置標記」，換成 .lnk 靠 `fix_video_links.py`。
2. **不要用檔名標題比對／猜路徑**——目標解析只信行尾「｜原路徑」與 URI 本身。
3. **PowerShell 暫存檔不要寫進 KB／`_video_links`**（早期版本踩過：`_batch.json` 殘留）。
4. **逾時＋重試防護不要拆**（本日實測卡死過一次）。
5. **「有捷徑沒建成就不改任何條目」的順序不要反**（避免 md 指向不存在的 .lnk）。
6. `subprocess` 抓 PowerShell 輸出用 `capture_output=True`（bytes）自行 decode，
   `text=True` 在 cp950 環境會炸 `UnicodeDecodeError`。
7. KB 不進 git：改條目不需 commit；但工具／排程／文件改動要 commit push。
